# Inclusion & Exclusion Criteria (IC/EC)

## Inclusion Criteria (IC)

- **IC-P (Population):** Studies focusing on black-box test case generation, acceptance testing (UAT), or requirement-based testing from software requirements specifications (e.g., PURE dataset).
- **IC-I (Intervention):** Studies evaluating Large Language Models (LLMs) like ChatGPT, Claude, or similar models using prompting techniques (such as one-shot or few-shot) for test generation, specifically targeting Equivalence Partitioning (EP) or Boundary Value Analysis (BVA).
- **IC-O (Outcome):** Studies reporting quantitative evaluation metrics related to test coverage, requirements coverage, item coverage %, or fault detection capabilities.
- **IC-S (Study Design):** Peer-reviewed empirical experimental studies, journal articles, or conference papers.

## Exclusion Criteria (EC)

- **EC-1 (Domain Misalignment):** Papers not related to software engineering or black-box test design (e.g., code synthesis without test generation, white-box unit test execution only).
- **EC-2 (No LLM Evaluation):** Papers using traditional non-LLM automated test generation tools (e.g., Evosuite, Randoop) without comparing against LLMs.
- **EC-3 (No Coverage/Quantitative Metric):** Qualitative opinion pieces, editorials, extended abstracts, posters, or position papers lacking empirical quantitative results.
- **EC-4 (Full-text Inaccessible):** Papers with unavailable full text or restricted access via paywall under standard academic access protocols.
- **EC-5 (Language):** Non-English publications.
- **EC-6 (Duplicate):** Duplicate records or earlier versions of a more comprehensive study.
